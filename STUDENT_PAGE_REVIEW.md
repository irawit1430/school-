# Student page review

Implementation follow-up: [Student page fixes and verification](<C:/Users/ANURAG TIWARI/Desktop/school/STUDENT_PAGE_FIXES.md>). The findings below record the original pre-fix audit.

Completed 9 September 2026. Scope: `/students`, its summary cards and six dialogs, relevant API helpers, dashboard layout, and global-search integration.

This is a source review. No browser was opened, no live API requests were made, and no application code was changed. Layout findings describe risks supported by the CSS; their exact appearance has not been visually measured. Existing unrelated workspace changes were left untouched.

Priorities: **P1** = address first because of incorrect identity/data, misleading live status, or a blocked core flow. **P2** = functional, usability, or accessibility gap. **P3** = lower-impact presentation inconsistency.

**Highest-priority findings**

1. **P1 — A message draft can be sent to a different student's parent.** Write a message for student A, close it, and open messaging for student B. Opening/closing changes only `messageStudent`; the old subject/body remain. Sending uses B's parent ID. Clear the draft when the recipient changes, or store drafts by recipient. Show the actual parent destination before Send. [Open action](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:497>), [send/reset](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:129>), [close](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:645>).

2. **P1 — The next route assignment can lose every stop after the first save.** Opening assignment loads full routes and sets `fullRoutesLoaded`. Saving calls `loadData()`, which replaces them with summaries containing no stops, while the flag remains true. The next dialog skips the full fetch and cannot select a stop. A slow summary response can also overwrite full data. Keep summaries and full route details separate, or invalidate/refetch them consistently. [Summary refresh](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:63>), [full-route flag](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:88>), [API shape](<C:/Users/ANURAG TIWARI/Desktop/school/lib/api.ts:323>).

3. **P1 — Attendance presented as real time stays frozen.** Data loads on mount and after create/import/assignment. There is no periodic refresh, attendance subscription, or normal-state Refresh button. A student who drops off after the page opens can remain shown as currently boarded; exports and alerts use the same old snapshot. Add controlled refresh, a visible update time, and day-rollover handling. [Initial load](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:81>), [real-time description](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:377>).

4. **P1 — CSV header guessing can replace a student's name with a parent's name.** For `Parent Name,Student Name,Roll Number,Phone`, the importer picks `Parent Name` as both student and guardian name. The loose `id` match can also choose `RFID Tag` as the roll-number column. Use an explicit header map and display the mapped fields before import. This mapping error was reproduced with an isolated JavaScript example; no records were submitted. [Header detection](<C:/Users/ANURAG TIWARI/Desktop/school/lib/api.ts:538>).

**Other functional and logical UI gaps**

5. **P2 — Invalid import rows disappear without explanation.** Rows missing name or roll number are filtered out before the API request. A successful response can therefore look like a complete import when rows were omitted. Show row numbers, reasons, and imported/rejected totals; do not silently discard records. [Filtering](<C:/Users/ANURAG TIWARI/Desktop/school/lib/api.ts:556>), [success handling](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:179>).

6. **P2 — Valid quoted CSV content is not parsed correctly.** Splitting into lines before parsing breaks quoted multiline fields; doubled quotation marks are not unescaped. Use a parser that supports quoted records and report malformed rows before submitting. [Line splitting](<C:/Users/ANURAG TIWARI/Desktop/school/lib/api.ts:535>), [field parsing](<C:/Users/ANURAG TIWARI/Desktop/school/lib/api.ts:549>).

7. **P2 — Import requires a schema that the dialog never explains.** Name, roll/ID, guardian/parent name, and phone/contact columns are required, yet there is no downloadable sample or list of required headers. The error says to check a template that is not available in this flow. Extra grade, email, or RFID fields are also not included in the generated payload. Provide a template, accepted-field guidance, and warnings for ignored columns. The attendance export cannot substitute for this template because it lacks guardian fields. [Dialog](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/students/ImportStudentsModal.tsx:39>), [required headers](<C:/Users/ANURAG TIWARI/Desktop/school/lib/api.ts:544>), [payload](<C:/Users/ANURAG TIWARI/Desktop/school/lib/api.ts:550>).

8. **P2 — Message Parent is offered without a parent account.** The page supports guardian-phone-only records, but the action is always available and submission checks only for a student. Missing `parentId` produces a request to `/parents/undefined/messages`. Disable the action with an explanation or offer the available contact method. [Action](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:497>), [submit guard](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:124>), [endpoint](<C:/Users/ANURAG TIWARI/Desktop/school/lib/api.ts:425>).

9. **P2 — Closing a dialog does not stop its pending write.** Add, Message, and Assign can close through Cancel, X, Escape, or backdrop during submission. Import disables Cancel but leaves other dismissal paths active. If another form is opened before the first request finishes, the old completion handler can close or clear the new form. Guard all dismissal paths during saving, or scope completion to its originating operation. [Shared dismissal hook](<C:/Users/ANURAG TIWARI/Desktop/school/hooks/useClickOutside.ts:7>), [Add](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/students/AddStudentModal.tsx:21>), [Import](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/students/ImportStudentsModal.tsx:15>), [completion handlers](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:109>).

10. **P2 — The donut disagrees with its legend.** The legend has five statuses, but the gradient draws only Boarded, Dropped off, and a gray remainder. Leave and no-show students are visually merged into gray, despite purple/red legend entries. Generate every segment from the same status dataset. [Legend data](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:333>), [gradient](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:532>).

11. **P2 — Global search does not update the existing Students page.** The page reads `q` once when initializing local state. Selecting another student while already on this route changes the URL but leaves the earlier filter. Query-history navigation has the same gap. React to query changes, and ensure a previously selected status tab does not hide a globally selected student. [Search initialization](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:50>), [global navigation](<C:/Users/ANURAG TIWARI/Desktop/school/components/layout/Header.tsx:245>).

12. **P2 — Unavailable data is displayed as reassuring empty/zero data.** Notification loading/failure can display “No recent alerts” because only console warnings are recorded. Separately, `fetchStats` swallows errors and returns `{}`, which becomes zero Late Arrivals. Track loading, unavailable, and successfully empty states separately and offer retry. [Notification failure](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:64>), [empty message](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:596>), [stats fallback](<C:/Users/ANURAG TIWARI/Desktop/school/lib/api.ts:271>), [zero rendering](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/students/SummaryCards.tsx:65>).

[Reset effect](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:325>), [row slice](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:452>), [count](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:518>).

**Spacing, responsive layout, and accessibility**

25. **P2 — A tall alerts rail creates a large blank area in the student table.** At the desktop grid breakpoint, both columns stretch to the same height. The table panel uses a growing body and bottom-pushed pagination, while the adjacent rail renders every returned alert, normally up to 20. With a long rail and at most eight rows, the table gains unused vertical space. Top-align the two panels and show a compact alert list with a separate full-list path. [Grid and panel](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:410>), [growing body](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:439>), [footer](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:517>), [alert limit](<C:/Users/ANURAG TIWARI/Desktop/school/lib/api.ts:403>).

26. **P2 — The page heading and three actions lack narrow-screen reflow.** The title/description and action group remain horizontal flex rows, with no wrapping or mobile stacking. Long button labels compete with the heading on phones and narrow content widths. Stack the heading above actions, allow wrapping, and reduce outer padding at small widths. Apply the same structure to the loading skeleton. [Page header](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:373>), [loading header](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:344>).

27. **P2 — The summary rail is too narrow at the first desktop breakpoint.** At a 1024px viewport, the 256px sidebar and page padding leave approximately 720px for the four-column grid. After gaps, the rail is about 162px wide, leaving about 112px inside its padded card for a requested 160px donut. It must shrink/distort or overflow. Keep the rail below the table longer, use a minimum viable rail width, or size the chart to its container with a preserved aspect ratio. These are source-derived dimensions, not browser measurements. [Dashboard width](<C:/Users/ANURAG TIWARI/Desktop/school/app/(dashboard)/layout.tsx:43>), [grid](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:410>), [card/chart](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/StudentsAttendance.tsx:527>).

They have no viewport height limit or scrollable body and no outer padding. A short screen, zoom, or virtual keyboard can make controls unreachable. Use viewport padding, a height constraint, and a scrolling body with reachable actions. Credentials already has a height limit and should be treated separately. [Add](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/students/AddStudentModal.tsx:24>), [Assign](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/students/AssignBusModal.tsx:28>), [Profile](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/students/StudentProfileModal.tsx:18>).

Credentials always uses two columns, truncates email, and does not wrap long passwords. Stack fields on narrow widths, constrain value columns, and allow long values to wrap or be explicitly copied. [Profile fields](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/students/StudentProfileModal.tsx:35>), [credential grid](<C:/Users/ANURAG TIWARI/Desktop/school/components/views/students/CredentialsPopup.tsx:42>).
